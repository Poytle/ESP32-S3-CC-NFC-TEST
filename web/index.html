02 / Signing laboratory

Synthetic keys, real cryptography. ESP32 generates a root, issuer, and demo card key at boot. The root signs the issuer public key; the issuer signs the demo card public key. The demo card signs a fresh random challenge.

Run the demo to inspect the proof.

What this proves

The demo checks both certificate links, verifies the challenge signature, and rejects that signature against a modified challenge and a fresh challenge. This illustrates the trust chain and replay resistance behind dynamic authentication.

Live card certificates and any dynamic signature returned by GPO are displayed as unverified bytes. This firmware does not implement EMV RSA certificate recovery, scheme trust anchors, DDA, fDDA, CDA, or issuer authorization. It cannot establish that a scanned payment card is genuine or authorize entry. UID and last four digits are not secure identifiers.

Inspection sends SELECT, GET PROCESSING OPTIONS with zero amount, and READ RECORD only. A payment card may still update its internal state during GPO. There is no GENERATE AC, PIN attempt, payment, card write, or arbitrary APDU console.
