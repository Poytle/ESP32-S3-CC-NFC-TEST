CA public key and enrollment

A card does not expose its RSA public modulus directly: its issuer-signed certificate must be recovered using the issuer key, which is recovered using the matching scheme CA public key (CAPK). The card row shows the required RID and CA index. Import that public key below, retap, then press Enroll public key after a successful signature check.



What a verified retap means
RETAP VERIFIED means a signature covering this tap’s fresh challenge verifies with the public key you enrolled. PAN selects the record; PAN matching alone never passes verification. Enrollment is saved in ESP32 flash, including the public key and a PAN/application lookup digest. Clear cards clears scan history, not enrollment.
This is a key-continuity demo. Certificate hashes, key assembly and PAN bindings are checked during recovery, but imported CAPK provenance, certificate expiry and revocation are not validated. A verified signature does not establish bank approval or cardholder identity and does not prevent live relay attacks. The open WiFi admin interface is suitable for this lab, not a deployed entry controller.
Supported proofs: RSA/SHA-1 DDA with DDOL 9F3704 and Visa fDDA v1 with the required transaction inputs and 9F69. Other schemes/modes, including CDA, may remain unsupported. All recovery and signature checks run on the ESP32.
